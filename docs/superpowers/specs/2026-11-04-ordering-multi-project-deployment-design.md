日期：2026-11-04

## 目标

在一台新的云服务器上运行多个互不干扰的个人项目。每个项目维护自己的容器与数据卷；整机只有一个 HTTPS 入口；此仓库通过 CI 验证、构建带 Git 提交 SHA 的镜像，再以可回滚的方式发布。微信小程序只访问本项目的域名。

本设计针对当前仓库：原生微信 TypeScript 小程序、Next.js 16 API 与管理后台、MySQL 8.4、Prisma 7。小程序是微信发布物，不是服务器上的前端容器。Next.js 已同时提供 `/api/v1/*`、`/admin/*` 和 `/media/*`。

- 旧部署记录描述的是重装前的服务器状态，不能用来推断当前 `8.137.174.33` 上仍有 Nginx、MySQL 或旧数据。首次连接后以只读检查为准。

## 方案比较

1. **共用 Caddy，直接代理各项目应用**：Caddy 独立运行并独占 80/443；每个项目的 Compose 只把应用接入共用网络。容器数少，证书由 Caddy 自动管理。需要把当前 Nginx 的请求体上限、安全响应头和边缘限流重做。
2. **共用 Caddy，项目内部保留 Nginx（本项目采用）**：保留原有 Nginx 限流和响应策略，Caddy 负责域名与 HTTPS。多一层代理和容器，但可在迁移时保持边缘保护。项目 Nginx 只在宿主机 `127.0.0.1` 的独立端口监听；Caddy 容器使用 Linux 主机网络并代理到该端口。Caddy 覆盖真实客户端 IP 请求头，Nginx 只信任来自本机入口的值。
3. **每个项目分别暴露 Nginx**：无需重写当前边缘规则，但多个项目会争用宿主机 80/443，不符合单机多项目共用入口目标。

方案 2 是实施决定，原因是当前 Nginx 已经提供普通 API、微信认证和管理员登录限流，以及两种上传的体积上限、响应头和图片缓存策略。应用内限流仅保存在进程内，重启会重置。新 Nginx 只处理 HTTP，不保存证书；限流键必须来自经 Caddy 覆盖的客户端地址头，而非 Docker 网关地址。

## 域名与路由

每个项目分配一个独立子域名。本项目使用 `ordering.guziyi.cn`，同时承载 `/api/v1/*`、`/admin/*`、`/media/*` 和健康检查。其他项目各用自己的子域名，内部仍可沿用相同的 `/api/v1` 前缀。新域名和证书生效、微信公众平台合法域名更新后，才修改小程序 `apps/miniapp/src/config.ts` 的生产地址并发布新版本。

## 容器与网络

整机入口单独维护一个 Caddy Compose 项目，持久化 `/data` 与 `/config` 以保存证书和配置。Caddy 在 Linux 主机网络中独占 80/443，项目 Nginx 只映射到 `127.0.0.1:18080`（该项目的预定端口，部署前检查冲突）。每个应用项目使用独立 Compose 项目名、独立数据卷、独立内部网络。MySQL 和 Next.js 不映射宿主机端口。容器内的健康检查请求本机 3000；外部检查通过 HTTPS 域名执行。应用和数据库使用资源上限与轮转日志；服务器容量确定后再设具体数值。

## 构建与发布

CI 在 `dev`/`master`/`main` 的提交或 PR 上运行契约、Lint、类型、单元、集成和生产构建检查。生产发布由推送 `main` 触发；仓库当前尚无 `main`，建立/切换方式待确认。镜像至少包含应用与 Prisma tooling 两个产物，标签使用完整 Git SHA，并记录镜像摘要；禁止只用 `latest`。新服务器能稳定连接 GHCR 时，CI 推送镜像，服务器按摘要拉取。若实测连接不稳定，CI 构建后通过 SSH 传输镜像归档，保持同一 SHA 标识与发布门禁。

部署前验证环境、镜像、Compose 与磁盘空间，备份数据库和上传文件，再执行向前兼容的 Prisma 迁移。更新应用后检查容器健康与公网 HTTPS。失败时恢复之前的应用镜像，数据库不自动逆向迁移。保留上一个镜像和发布记录，提供显式回滚命令。发布脚本只操作本项目容器和卷，不重启其他项目或共用 Caddy。

## 数据与恢复

旧数据已不存在，不执行迁移。首次部署创建空数据库并运行 Prisma 迁移；菜单种子含菜品和图片，是否导入由用户在上线前确认。确认空库状态与上传卷持久化后再启用新域名与小程序请求。后续每日备份数据库和上传卷，并将加密副本写入阿里云 OSS；需要独立恢复演练。

新服务器上的日常备份覆盖 MySQL 和上传文件，存放于本机受限目录并复制到异地对象存储。至少做一次独立恢复演练后，才把备份标记为可用。备份、证书、磁盘和应用健康异常应有可见告警；凭据和数据库内容不得进入 CI 日志。
